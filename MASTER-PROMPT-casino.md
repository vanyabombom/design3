## Стек — жёсткое ограничение

Статическая генерация. HTML, CSS, ванильный JS, ноль рантайм-зависимостей:
`package.json` с пустыми `dependencies`/`devDependencies`, в проекте нет
`node_modules`. Node 24, ESM. **Нельзя: WordPress, любая CMS, React, Vue,
Next.js, jQuery, Bootstrap и другие тяжёлые библиотеки.** Админки нет,
контент должен индексироваться без проблем.

Оффлайн-тулинг проверки (headless-браузер для скриншотов/замеров) под запрет
не попадает — в `dist/` из него не уезжает ни байта, ставится отдельно от
проекта.

```
node build.js                 сборка в dist/
node build.js --lint-only     только проверка, без записи файлов
node build.js --stage=content ужесточить правила контента до ошибок
node serve.js [порт]          посмотреть dist/ локально (301 из dist/_redirects работают)
```

## Принципы, зашитые в движок

- **Бренд заводится один раз** в `data/brands.de.json`. Все листинги —
  пересечение `бренд × таксономия` по декларативным правилам `match` из
  `taxonomies.json`. Списков брендов для страниц не существует как данных.
- **Оценка не проставляется руками.** `score.total` нигде не хранится,
  считается из `criteria.json` при каждой сборке; попытка записать готовую
  оценку в данные ловит линтер. `/how-we-test/` генерируется из того же
  файла — разойтись со страницей формула не может.
- **Честность зашита в движок.** Непроверенное поле = `null`, в таблице
  «noch nicht geprüft», а не правдоподобное число. Критерий без данных
  (`payout.provisional: true` и т.п.) **исключается** из расчёта
  (`skipWhen`), не получает ноль — ноль был бы утверждением, которого мы
  не проверяли. Покрытие видно на странице.
- **Линтер валит билд**, не оставляет предупреждением: партнёрская ссылка
  без `rel="sponsored nofollow"`, битая/висячая ссылка, страница без
  входящих (меньше трёх — предупреждение, ноль — ошибка), листинг без
  настоящего `<table>` с сортировкой, `<img>` без `width`/`height`/`alt`,
  отсутствие даты сверки, Lorem Ipsum, `official` в title, автор
  `admin`/`player`/`pin-admin`, уникальность соседних листингов < 40%
  (шинглы по 5 слов), офферы на странице ответственной игры,
  `AggregateRating` без опубликованной методики. `--stage=content` включает
  контентные правила как ошибки, до этого — предупреждения (контент ещё не
  написан).
- **Всё, что зависит от языка/страны, — в locale-файле.** Код и шаблоны не
  трогаются при смене ГЕО.
- **`basePath`** — префикс подпапки через `urlJoin`, позволяет показывать
  сайт на `IP/casino` до покупки домена и вернуть в корень одной строкой.
- **Волна публикации** — `includeTerms`/`aliasOf`. Незаполненные термы не
  получают страниц, отдают 301 на хаб, битых ссылок не возникает.
- **Вёрстка на `data`-атрибутах**, не на классах — сортировка и фильтры на
  ванильном JS работают по `data-sortable`, `data-f-*`, `data-value`.

## Дизайн-решения, утверждённые заказчиком

Результат правок с приёмки, не мой вкус — менять только если явно попросят:

- **Светлая тема, чёрного нет вообще** — единственная палитра, не

- **Свой SVG-набор**, ни эмодзи, ни иконочных шрифтов. Спрайт раз на

- **Первый экран отдан делу**: заголовок и прямой ответ слева, сводка
  цифрами справа. Таблица должна попадать во вьюпорт вместе с заголовком.
- **Колонка действий в таблице липнет к правому краю** — кнопки видны без
  доскролла на каждой строке. В ней теперь два действия одно под другим:
  **«Zum Casino»** (заливка акцентом, внешняя ссылка) и **«Zum
  Testbericht»** (обводка, иконка документа) — оба через `.cta`/`.btn`,
  паттерн `.cell-actions__stack` уже рассчитан на пару кнопок.
- **Логотипы настоящие, не перерисованные.** Чужой товарный знак не
  копируем приблизительно — либо официальный ассет, либо (до появления
  файла) монограмма с инициалами и устойчивым оттенком из слага; сборка сама
  подставляет файл, когда он появляется. Иконки платёжных методов — по типу
  метода, не логотип конкретного бренда, **но по актуальной правке — везде,
  где есть настоящий логотип метода, должен стоять он, а не обобщённая
  иконка**; сейчас 18/18 используемых методов покрыты.
- **Логотип, имя бренда и кнопка «Zum Casino» — кликабельны и ведут в одну
  точку** (см. «Партнёрская модель» ниже) — отдельная явная правка.
- **Элементы не должны слипаться** — отдельная претензия с приёмки, держать
  тап-таргеты ≥ 24×24 px (WCAG 2.2), паттерн компенсации padding —
  `.tap-link` в `assets/css/main.css`.

## Партнёрская модель — важно понимать перед правками

`affiliateLink()` в `lib/render.js` — единственное место, откуда выводится
ссылка на оффер по всему проекту (rel и `data-affiliate` проставляются там,
обойти технически нельзя). Сейчас она **всегда** ведёт на один общий адрес
`site.affiliate.logoLinkUrl` (сейчас `https://playcasino2026.com/PXdj858R?
a=aff35&z=SEP&p=cros`), независимо от бренда — это прямая правка заказчика:
логотип, имя бренда в таблице и кнопка «Zum Casino» должны вести в одно и то
же место. Честные пер-брендовые ссылки (`brand.affiliate.url`, поле
`site.affiliate.mode: "internal-redirect"` → `/go/<slug>/`) остались в
данных как заглушки (`track.example-affiliate.test`) и в рендере сейчас не
участвуют вообще. Если попросят вернуть модель «оффер на бренд» — обнулить
`site.affiliate.logoLinkUrl`, и `affiliateLink()`/`brandLogoLink()` сами
переключатся на `/go/<slug>/` → `brand.affiliate.url`. Кнопка «Zum
Testbericht» — единственный внутренний путь на страницу разбора бренда,
собирается прямой ссылкой на `/casino/casino/<slug>/`, партнёрской не
является и affiliateLink() не использует.

## Правила контента (лист 08/09 ТЗ, применяются к любому новому тексту)

- **Ни одного длинного тире (—) в пользовательском тексте.** Заменяется
  запятой, двоеточием или разбивкой на два предложения по контексту —
  не механической заменой на дефис.
- **Никаких маркеров ИИ-письма**: наду­тые формулировки о значимости,
  искусственные тройки, шаблонные «not X but Y», лишние вводные,
  чрезмерная симметрия «nicht X, sondern Y» на соседних абзацах,
  общие фразы вместо фактов.
- **Объём текста на странице — 5 000–7 000 знаков**, не меньше и не
  раздуто ради нормы.
- **Честность вместо правдоподобия** — см. принцип `null`/`skipWhen` выше;
  то же самое в прозе: не дописывать цифру, которой нет в источнике.
- Перед публикацией нового текста стоит прогнать его через навык
  `humanizer` (список конкретных паттернов и примеров «до/после» уже
  описан в его инструкции).

## Как проверять вёрстку

Меряется, не смотрится глазами — именно замером находили и уехавшую под
липкую колонку ячейку, и горизонтальную прокрутку страницы на 390 px,
которых на скриншоте не было видно.

Chrome в системе: `C:\Program Files\Google\Chrome\Application\chrome.exe`,
не зависимость проекта.

```
chrome.exe --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=4000 --window-size=1280,1000 \
  --screenshot=out.png http://localhost:4173/casino/
```

**Ловушка:** на Windows `--window-size` меньше ~500 px не работает — окно
упирается в минимальную ширину, картинка получается 390 px, а страница
внутри отрендерена на 500+ и обрезана. Мобильный вид так не проверить.

Правильный способ для мобильной ширины — страница-проба в `dist/` с
айфреймом нужного размера:

```html
<!doctype html><meta charset="utf-8"><style>body{margin:0}iframe{border:0;display:block}</style>
<iframe id="f" src="/casino/" style="width:390px;height:1200px"></iframe>
<pre id="out"></pre>
<script>
document.getElementById('f').addEventListener('load', function () {
  var d = this.contentDocument, root = d.documentElement;
  var wrap = d.querySelector('.table-scroll');
  document.getElementById('out').textContent = JSON.stringify({
    vw: root.clientWidth,
    pageOverflow: root.scrollWidth - root.clientWidth,   // обязан быть 0
    tableOverflow: wrap.scrollWidth - wrap.clientWidth,  // таблица скроллится внутри себя
    cols: [].slice.call(d.querySelectorAll('#offers thead th'))
      .map(function (th) { return th.textContent.trim() + '=' + th.getBoundingClientRect().width.toFixed(0); })
  }, null, 1);
});
</script>
```

Дальше `chrome.exe --headless=new --dump-dom` по адресу пробы и читаем
`<pre>`. Так же снимаются скриншоты мобильного и открытое состояние меню
(`details.open = true` скриптом). Удалить файл пробы после — следующая
сборка чистит `dist/`, но лучше явно.

В последних сессиях для скриншотов и тап-таргет аудита использовался
Playwright (headless Chromium) — ставится в отдельную scratch-папку вне
проекта, тот же принцип, что и с Chrome напрямую; глобальный кэш браузера
уже скачан на машине, повторная установка занимает секунды.

## Деплой

SFTP прямо в `/var/www/html`, конфиги nginx из `deploy/nginx/` — в
`/etc/nginx/conf.d/`, обязательно `nginx -t` перед `reload`. Порядок:
1) собрать (`node build.js --stage=content`, ждать 0 ошибок/0 предупреждений
по критериям приёмки), 2) залить конфиги, провалидировать, 3) залить
`dist/`, 4) `chown www-data:www-data` + `chmod 755` на выложенное,
5) `systemctl reload nginx`, 6) проверить снаружи curl'ом ключевые URL (200
на страницах, 301 на редиректах, 404 на несуществующих, что новые ассеты
отдаются) — не считать деплой готовым без внешней проверки.
