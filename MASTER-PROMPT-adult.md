## Стек — жёсткое ограничение

Статическая генерация. HTML, CSS, ванильный JS. Tailwind можно.
**Нельзя: WordPress, любая CMS, React, Vue, Next.js, jQuery, Bootstrap и
другие тяжёлые библиотеки.** Админки нет. Содержимое должно индексироваться.

Оффлайн-тулинг сбора данных (headless-браузер для скриншотов) под запрет не
попадает: в `dist/` из него не уезжает ни байта. Держать его отдельной папкой
со своим `package.json`, чтобы `dependencies` самого генератора оставались
пустыми — на приёмке смотрят именно туда.

Адаптив проверяется на 320, 768 и 1280 px. На мобильном не должно быть
горизонтального скролла всей страницы; таблицы скроллятся внутри своего блока.

## Что уже построено на казино — переиспользуй архитектуру

Собственный генератор на Node 24 ESM, **ноль зависимостей**. Прочитай
`README.md` и `build.js`. Раскладка:

```
build.js              сборка: данные → валидация → оценки → граф → рендер → линтер → dist
serve.js              локальный сервер с поддержкой 301 из dist/_redirects, порт 4173
lib/graph.js          страницы вычисляются из сущностей и таксономий
lib/match.js          декларативные правила отбора сущностей в листинг
lib/score.js          расчёт оценки из criteria.json
lib/lint.js           критерии приёмки как правила, валит билд
lib/render.js         загрузка шаблонов и разметка schema.org
lib/labels.js         title/H1/description из шаблонов локали
lib/schema.js         валидация карточки сущности
lib/sitemap.js        sitemap, robots, редиректы, конфиги nginx
lib/util.js           urlJoin, withBase, get/set по пути, даты
lib/icons.js          SVG-набор, спрайт, монограммы брендов
templates/_lib/layout.js   каркас документа и общие блоки
templates/*.js        по шаблону на тип страницы, экспорт render(ctx, page)
data/                 site.json, taxonomies.json, criteria.json, brands, locales, content
deploy/nginx/         конфиги, генерируются сборкой
```

Принципы, которые переносятся в каталог целиком:

- **Сущность заводится один раз.** Бренд лежит в одном JSON, все листинги
  генерируются пересечением `сущность × таксономия` по декларативным правилам
  `match`. Списков для страниц не существует как данных — они вычисляются.
  Для каталога это `сайт × категория`.
- **Оценка не проставляется руками.** Считается из `criteria.json` с весами
  при каждой сборке; попытка записать готовую оценку в данные ловится линтером.
  Страница методики генерируется из того же файла — разойтись они не могут.
  В казино шесть критериев: payouts 25, bonus 20, trust 20, games 15,
  payments 10, support 10, шкала 10.
- **Честность зашита в движок.** Непроверенное поле = `null`, а не
  правдоподобное число. Критерий без данных **исключается** из расчёта
  (`skipWhen`), а не получает ноль — ноль был бы утверждением, которого мы
  не проверяли. Покрытие показывается на странице.
- **Линтер на сборке** валит билд по критериям приёмки: партнёрские ссылки
  без `rel="sponsored nofollow"`, битые ссылки, страницы без входящих, `<img>`
  без `width`/`height`/`alt`, отсутствие даты сверки, Lorem Ipsum, таймеры
  срочности, фейковые счётчики, `AggregateRating` без опубликованной методики.
- **Всё, что зависит от языка и страны, живёт в locale-файле.** Слаги,
  шаблоны заголовков, подписи интерфейса. Код и шаблоны не трогаются.
- **`basePath`** — префикс подпапки, проходит через `urlJoin` (единственная
  точка сборки адресов). Позволяет показывать сайт по `IP/подпапка` до покупки
  домена, а потом вернуть в корень одной строкой конфига.
- **Волна публикации** — `includeTerms`. Незаполненные термы страниц не
  получают и отдают 301 на хаб, битых ссылок не возникает.
- **Вёрстка на `data`-атрибутах, не на классах.** Сортировка и фильтры на
  ванильном JS работают по `data-sortable`, `data-f-*`, `data-value` — смена
  дизайна не трогает поведение.

## Дизайн-решения, которые заказчик уже утвердил на казино

Переносить в каталог, если тема не потребует иного. Каждое из них — результат
правки с приёмки, а не мой вкус:

- **Светлая тема. Чёрного нет вообще** — не переключатель, а единственная
  палитра: тёмных токенов в CSS не осталось. Текст `#1f2733`, фон `#f4f6f8`,
  поверхности белые. Акцент разведён на два: тёмный для текста и линий,
  светлый для заливки кнопки — одним цветом на светлом фоне не выходит.
- **Никаких эмодзи и текстовых символов вместо иконок.** Свой SVG-набор,
  спрайт один раз на страницу, дальше `<use>`. Стрелки сортировки и шевроны
  аккордеона — маски из SVG в CSS, где `<use>` недоступен.
- **Компактная липкая шапка с бургером**, кнопка прижата к правому углу окна
  (шапка тянется во всю ширину, а не по колонке контента). Всё меню в панели
  на нативном `<details>` — без JS тоже работает; скрипт добавляет только
  Esc, клик мимо и закрытие при переходе.
- **Первый экран отдан делу.** Заголовок и прямой ответ слева, сводка цифрами
  справа в колонке, которая иначе пустует. Строка проверки в одну линию,
  раскрытие партнёрского статуса свёрнуто в одну строку. Таблица должна
  попадать во вьюпорт вместе с заголовком.
- **Кнопки действия видны всегда.** В таблице колонка действий липнет к
  правому краю, чтобы до «перейти» и «читать обзор» не нужно было
  доскроллить на каждой строке.
- **Графики должно быть достаточно**, но чужие логотипы не перерисовываем:
  это товарные знаки, и неточная копия хуже отсутствия. Пока файлов нет —
  монограмма с инициалами и устойчивым оттенком из слага. Сборка проверяет
  наличие файла и подставляет настоящий логотип автоматически, когда он
  появится. Иконки платёжных систем — по типу метода, не логотипы брендов.
- **Элементы не должны слипаться.** Отдельная претензия с приёмки.

## Как проверять вёрстку — важный приём

В системе стоит Chrome: `C:\Program Files\Google\Chrome\Application\chrome.exe`.
Это не зависимость проекта, скриншоты и замеры снимать им.

```
chrome.exe --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=4000 --window-size=1280,1000 \
  --screenshot=out.png http://localhost:4173/casino/
```

**Ловушка: на Windows `--window-size` уже примерно 500 px не работает** —
окно упирается в минимальную ширину, картинка получается 390 px, а страница
внутри отрендерена на 500+ и просто обрезана. Мобильный вид так проверять
нельзя, увидишь несуществующие баги.

Правильный способ — страница-проба в `dist/` с айфреймом нужной ширины:

```html
<!doctype html><meta charset="utf-8"><style>body{margin:0}iframe{border:0;display:block}</style>
<iframe id="f" src="/casino/" style="width:390px;height:1200px"></iframe>
<pre id="out"></pre>
<script>
document.getElementById('f').addEventListener('load', function () {
  var d = this.contentDocument, root = d.documentElement;
  var wrap = d.querySelector('.table-scroll');
  document.getElementById('out').textContent = JSON.stringify({
    vw: root.clientWidth,
    pageOverflow: root.scrollWidth - root.clientWidth,   // обязан быть 0
    tableOverflow: wrap.scrollWidth - wrap.clientWidth,  // таблица скроллится внутри себя
    cols: [].slice.call(d.querySelectorAll('#offers thead th'))
      .map(function (th) { return th.textContent.trim() + '=' + th.getBoundingClientRect().width.toFixed(0); })
  }, null, 1);
});
</script>
```

Дальше `chrome.exe --headless=new --dump-dom` по адресу пробы и читаем `<pre>`.
Так же снимаются скриншоты мобильного (айфрейм внутри широкого окна) и
открытое состояние меню (скриптом выставить `details.open = true`). Не
забыть удалить файлы пробы — следующая сборка чистит `dist/`, но лучше явно.

Мерить, а не смотреть глазами: именно замером нашлись колонка, полностью
уехавшая под липкую колонку действий, и 41 px горизонтальной прокрутки
страницы на 390 px, которых на скриншоте было не видно.

## Задача: каталог

**Модель:** сеть лендингов, **один домен = одна категория**. Домен содержит
точное вхождение ключа (`freeporntubesites.com`, `aipornsites.com`). Трафик по
категорийным запросам → рейтинг сайтов → переход по партнёрской ссылке.

**Объём одного лендинга:** 1 главная + 15–40 внутренних (подкатегории,
сравнения, гайды, карточки крупных сайтов). В топ-листе 20–50 сайтов.

**Карта категорий:** 191 штука, лист `06_КАТЕГОРИИ (191)` — слаг, группа,
предлагаемый домен. Данные чистые: 191 строка ровно, дублей слагов и доменов
нет, разбивка по группам сходится с листом 01 до штуки. Можно грузить как есть.

| Группа | Сколько | Конкуренция |
|---|---|---|
| Ниши и фетиши | 88 | низкая — **главный резерв, начинать отсюда** |
| Премиум | 37 | средняя |
| Камы и чаты | 19 | высокая |
| AI-порно | 19 | низкая и растущая |
| Бесплатные тубы | 11 | очень высокая — в последнюю очередь |
| Хентай и анимация | 5 | средняя |
| Соцсети и OF | 4 | высокая |
| Знакомства, VR, картинки, игры, торренты | 8 | точечно |

**Структура лендинга** (лист 02, приоритет 1): H1 + прямой ответ в 40–70 слов →
топ-3 крупными карточками → основной список 20–50 позиций → фильтры (цена,
качество, регистрация, реклама) → сортируемая таблица сравнения → «как мы
отбирали» с весами → FAQ 6–10 вопросов → футер с 18+ и раскрытием партнёрского
статуса. Приоритет 2: подкатегории, гайд, блок обновлений.

**Карточка сайта** (лист 03) — обязательные поля: название, домен, скриншот
WebP 640×400, фавикон 64×64, категория, оценка 0–10 по формуле, краткое
описание 2–3 строки, полное 200–400 слов, цена (бесплатно/фримиум/платно),
регистрация, уровень рекламы, дата проверки, статус. Необязательные: качество
видео, мобильная версия.

**Пайплайн** (лист 04): отбор категории → сбор 20–50 сайтов → проверка
доступности → скриншот через headless-браузер → фавикон → сбор фактов →
описание по фактам → расчёт оценки → публикация → еженедельный мониторинг
мёртвых доменов.

**SEO** (лист 05): title 60–65 знаков с ключом в начале и годом в конце;
description 140–158 с цифрой (сколько сайтов); ItemList + FAQPage +
BreadcrumbList + Article с `dateModified`; WebP с явными размерами и lazy ниже
первого экрана; LCP < 2,5 с; **не более 3–5 ссылок на другие домены сети,
только из тела, не сквозным блоком**; возрастной баннер обязателен.

## Что нужно решить до старта

1. **Откуда берём список сайтов.** ТЗ требует собирать самим (Similarweb,
   известность, обход конкурентов), а не парсить чужой каталог. Есть ли
   доступ к Similarweb или собираем вручную. Без ответа не начинаем сбор:
   выдумывать трафик нельзя.
2. **Какую категорию делаем первой и под каким доменом.** По логике ТЗ —
   что-то из AI-группы: ниша молодая, партнёрские программы у AI-генераторов
   платят и не требуют разрешений.
3. **Партнёрские программы и шаблон ссылки** — или работаем с заглушками.
   На казино в итоге вообще не по-брендово: завели один общий URL на все
   бренды сайта (`site.affiliate.logoLinkUrl`) по прямой правке заказчика,
   честные пер-брендовые ссылки (`brand.affiliate.url`) так и остались
   заглушками и в рендере не используются. Для каталога это, скорее всего,
   не подойдёт — там оффер как раз разный на каждый сайт-карточку, спроси
   явно, прежде чем повторять казино-схему.
4. **Форкаем в отдельную папку рядом или веткой в этом же репозитории.**
5. **Исключаем ли 10 товарных категорий** на первом этапе.
6. **Дизайн.** Жду несколько вариантов на выбор перед разработкой. Требования
   те же, что были по казино, с поправкой на утверждённое выше: юзабельно,
   простенько, не «иишно», светлая тема без чёрного.
7. **План по LCP.** 40 скриншотов на страницу — главный риск, ТЗ говорит об
   этом прямо. Моё предложение: в основном списке превью 320×200 WebP
   (12–18 КБ), в топ-3 полноразмерные 640×400 с `fetchpriority="high"`,
   `loading="lazy"` с четвёртой позиции, явные `width`/`height` везде,
   `content-visibility: auto` на элементах списка, фавиконы одним спрайтом.
   Тогда первый экран — три картинки, а не сорок.
